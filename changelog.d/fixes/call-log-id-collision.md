- **fix(logging):** widen the chat trace id from 24 to 64 bits so it can key `call_logs`. The id chatCore mints per attempt is written to `call_logs.id` (`id TEXT PRIMARY KEY`) and carried by the paired `request.started` event (#13481), but it was `randomUUID().slice(0, 6)` — 16,777,216 values. The collision is birthday-shaped against the rows already stored rather than a concurrency race: with N rows in the table each insert collided with probability N/2^24, about 1.6% at 268k rows. The losing insert throws inside `saveCallLogOperation`, which logs and swallows it, so the row was dropped with no signal to the caller and call analytics, combo provider stats and cost rollups silently undercounted (#14338).
